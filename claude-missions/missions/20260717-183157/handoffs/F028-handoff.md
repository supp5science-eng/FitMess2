## Decisions made
- **`src/lib/dates.ts` uses no external timezone library** — the platform's own `Intl.DateTimeFormat` with `timeZone: "Europe/Belgrade"` already carries full, current IANA tzdata in Node 22 / evergreen browsers, so a dependency (`date-fns-tz`/`luxon`/`moment-timezone`) would add weight for zero benefit; `tech-decisions.md` names no specific tz library, so this was a from-scratch technical choice, verified correct against hand-computed UTC offsets for both CET/CEST and both 2026 DST transition dates in the unit tests (23h/25h day-length assertions), not just against my own implementation's self-consistency.
- **The offset-detection technique** (`getTimeZoneOffsetMs`: format a UTC instant's wall-clock components in the target zone, then re-interpret those SAME components as UTC; the delta is the zone's offset) is the standard technique real timezone libraries use internally — chosen over hardcoding EU DST transition rules (which would need yearly maintenance) or a lookup table.
- **Belgrade local midnight is always unambiguous** — EU-wide DST transitions happen at 01:00 UTC (02:00→03:00 local in spring, 03:00→02:00 local in autumn), never crossing local midnight itself, so "start of day" needs no special-case handling for the transition days themselves (verified, not just assumed, via the 23h/25h tests).
- **`getTodayRange`'s public shape (`{ startIso, endIsoExclusive }`) was deliberately kept identical** — F027's handoff explicitly scoped this swap to be a single-function-body change; honored that exactly, so `src/lib/home/today.ts`, `/danas`'s page, and every one of F027's own component tests needed zero changes.
- **`AddSheet` reuses the exact "no shadcn Sheet/Dialog primitive exists" overlay pattern** F026's `LogEditSheet`/`LogDeleteConfirm` and F019's `DeleteAccountDialog` already established (`fixed inset-0` backdrop + `role="dialog"` + self-contained trigger/open-state) rather than introducing a new overlay primitive or pulling in a new dependency — consistent with the existing codebase, not a new pattern.
- **The FAB is positioned via a `fixed inset-x-0` full-viewport-width wrapper containing an inner `mx-auto max-w-[430px]` column with the button right-aligned inside it**, rather than a plain `fixed right-6 bottom-24` — this mirrors `AppShell`'s own `mx-auto max-w-[430px]` centering exactly, so the FAB stays visually anchored to the same centered mobile-width column on desktop (AS-126) instead of pinning to the actual browser viewport's right edge, while still remaining `position: fixed` (visible while scrolling) rather than `absolute` (which would scroll away on a tall page).
- **Stubbed methods route to a real placeholder page (`/dodaj/uskoro/[metoda]`) rather than a disabled/inert row** — the clarified scope's own wording ("route them to a clear Serbian 'uskoro' placeholder ... (or disabled state)") names routing as the primary option; chose it because it makes "starting a method" a real, literal, testable 2-tap user action (tap "+", tap the method, land on a real screen) for ALL four methods uniformly, not just the one built one — and because a future F030/F062/F064 only needs to swap that one row's `href`, no sheet-structure change.
- **`/dodaj/uskoro/[metoda]` is one dynamic route with a method→copy lookup table (+ a generic fallback for any unrecognized value)**, not three separate static routes — less duplication, and the defensive fallback means even a stale/mistyped link never crashes (clarified failure-handling answer: "never a blank/broken screen").
