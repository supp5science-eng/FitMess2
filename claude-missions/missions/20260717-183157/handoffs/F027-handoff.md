## Decisions made
- **Day boundary is a deliberately swappable, non-Belgrade-aware helper** (`src/lib/home/today-range.ts`'s `getTodayRange`) — per the clarified scope note ("'Today' = for now use the user's local/day; F028 will formalize Europe/Belgrade day boundaries"), this uses plain server-local `Date` component math rather than `tech-decisions.md`'s "never raw `new Date()` day math" convention. This is a documented, intentional, scoped-out-of-this-feature deviation, not an oversight — see "Notes for the next worker" below for exactly what F028 needs to swap.
- **Two round trips + application-code join** (`getTodayData` → `attachFoodToLogs`) rather than an embedded Supabase `select("*, food:foods(*)")` — matches the existing precedent `src/lib/food/recents.ts`'s `getRecentFoods`/`reorderFoodsByIds` already established in this codebase (same rationale: keeps both queries simple, RLS-governed, and independently unit-testable with plain fixtures).
- **Ring never turns red/alarming on overshoot** — stays the single green accent (`var(--primary)`) at a full 100% fill; only the center copy changes ("Preostalo" → "Prekoračeno" + one reassuring sentence). This is a direct implementation of the clarified "zero-shame tone" / "one bad day is small" philosophy from the mission brief, not something any single assertion's text explicitly demanded on its own — flagging it here as a deliberate design choice.
- **Client state in `HomeScreen` is a plain `useState<LogWithFood[]>` seeded from server props**, mutated only by `LogEditSheet.onSaved`/`LogDeleteConfirm.onDeleted` callbacks (both server-confirmed responses, not blind optimistic guesses) — matches the clarified "server as source of truth; small client state (form/optimistic) only" data-shape answer. Creating a brand-new log is handled by a DIFFERENT route (`/dodaj/porcija/[foodId]`, F025) that client-navigates back here; deliberately did NOT touch that already-shipped component to keep this feature's "Touches" scoped to home-screen files only — Next's dynamic (cookie-reading) rendering for `/danas` means that `router.push` already re-fetches fresh Server Component data on landing, which the real-browser walkthrough confirms.
- **Macro-bar fill is visually capped at 100% but the numeric label is never clamped** — a macro consumed beyond its target still shows the real number (e.g. "248 / 60 g" in the overshoot screenshot), matching the ring's own "the number is real, never hidden" posture for AS-050.
- **A log whose `food_id` is null (food since deleted) hides the edit control on its meal card but keeps delete available** — `LogEditSheet` requires a full `Food` row to compute its live preview; delete never needs one. This reuses the exact edge case F026's handoff already documented and left untested at the data layer (`LOG_FOOD_UNAVAILABLE_ERROR_SR`) — this feature adds the missing-food UI handling on top without re-testing that server-side edge case itself (out of this feature's scope).
- **Portion label reuses `findMatchingCommonUnit`** (F026) to show e.g. "2 × parče (100 g)" when a log's grams exactly match a common unit, falling back to plain "`{grams} g`" otherwise — same helper F026's edit sheet uses to pre-select a unit, applied here purely for display.
- **No-target state is a plain informational message, not a redirect** — a user should never reach `/danas` without a target row (`src/middleware.ts` gates on `profiles.onboarded_at`, and onboarding always inserts a target row in the same transaction-equivalent flow, `src/lib/onboarding/persist.ts`), but this is handled defensively anyway (never a blank/broken screen) rather than assumed to be unreachable.
