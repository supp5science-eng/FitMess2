## 3. Posao za kući — tačnim redom

### 3.1 JDK (jednokratno, ~2 min)

`keytool` dolazi uz JDK, kog na mašini nema.

```powershell
winget install Microsoft.OpenJDK.21
```

Otvori **nov** terminal, pa proveri: `keytool -help`

### 3.2 Keystore

Codemagic personal account nudi **samo upload**, ne generisanje — zato ide ručno.

```powershell
cd ~/.secrets
keytool -genkeypair -v -keystore fitmess-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

- **Lozinku** izmisli i odmah zapiši u `~/.secrets/`. Kad pita „key password",
  pritisni Enter da preuzme istu (PKCS12 koristi jednu).
- **Ime, organizacija, grad, država** — ne vidi se korisniku, samo metapodatak
  sertifikata. Svoje ime i `RS`.
- `-validity 10000` je ~27 godina; Play traži važenje bar do 2033.

Zatim: Codemagic → Settings → Code signing identities → **Android keystores** →
Choose a file.

| Polje | Vrednost |
|---|---|
| Reference name | `fitmess-upload` — **tačno ovako**, yaml ga traži po imenu |
| Key alias | `upload` |
| Obe lozinke | ona koju si izmislio |

Backup: fajl već stoji u `~/.secrets/`. Dodaj kopiju van tog diska.

> **Ispravka dokumenta:** u `izlazak-u-store.md` piše „keystore se gubi jednom i
> zauvek". To važi za *app signing key*. Ako prihvatiš **Play App Signing**
> (podrazumevano za nove aplikacije), Google drži taj ključ, a tvoj je samo
> *upload key* — koji se, ako se izgubi, resetuje zahtevom Google-u. Svejedno
> čuvaj backup.

### 3.3 `claude-missions/android/app/build.gradle`

```gradle
android {
    namespace = "app.fitmess"
    compileSdk = rootProject.ext.compileSdkVersion

    // Codemagic izvozi ove promenljive kad workflow referencira keystore
    // preko `android_signing:`. Lokalni build (bez njih) i dalje radi — samo
    // pravi nepotpisan release, što je ispravno: ključ nije na disku.
    signingConfigs {
        release {
            if (System.getenv("CM_KEYSTORE_PATH")) {
                storeFile file(System.getenv("CM_KEYSTORE_PATH"))
                storePassword System.getenv("CM_KEYSTORE_PASSWORD")
                keyAlias System.getenv("CM_KEY_ALIAS")
                keyPassword System.getenv("CM_KEY_PASSWORD")
            }
        }
    }

    defaultConfig { /* nepromenjeno */ }

    buildTypes {
        release {
            if (System.getenv("CM_KEYSTORE_PATH")) {
                signingConfig signingConfigs.release
            }
            minifyEnabled false
            proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        }
    }
}
```

### 3.4 Novi workflow u `codemagic.yaml` (ispod `ios-testflight`)

```yaml
  android-play:
    name: FitMess Android → AAB
    max_build_duration: 60
    instance_type: linux_x2
    working_directory: claude-missions

    environment:
      node: 22
      java: 21          # AGP 8.13 ne radi na starijem JDK-u
      android_signing:
        - fitmess-upload   # mora da se poklopi sa imenom u Codemagic UI

    scripts:
      - name: Install npm dependencies
        script: npm ci

      - name: Sync the Capacitor Android project
        # Isti razlog kao na iOS-u: ovo piše `android/app/src/main/assets/
        # capacitor.config.json` sa `server.url` i `FitMessApp/1.0`. Fajl je
        # gitignore-ovan, pa bez ovog koraka ljuska nema sajt da učita.
        script: npx cap sync android

      - name: Bump versionCode
        # Play odbija AAB sa versionCode koji je već viđen na bilo kom tracku,
        # uključujući obrisane. PROJECT_BUILD_NUMBER raste sam po workflow-u.
        script: |
          set -e
          sed -i "s/versionCode .*/versionCode ${PROJECT_BUILD_NUMBER}/" android/app/build.gradle
          grep -n "versionCode" android/app/build.gradle

      - name: Build the AAB
        script: |
          chmod +x android/gradlew
          cd android && ./gradlew bundleRelease

    artifacts:
      - android/app/build/outputs/**/*.aab
      - android/app/build/outputs/**/mapping.txt
```

**Namerno nema `publishing: google_play:`.** Google Play API **ne prima prvi
upload** — prvi AAB se ručno prevlači kroz Play Console. Tek posle toga ima
smisla dodavati service account.

Pokretanje: isto kao iOS, samo `"workflowId": "android-play"`.

**Tri stvari iz ove predaje su bile netačne ili već rešene:**

1. **Ime u draftu je već bilo `FitMess`**, ne „FitMess: kalorije bez stresa".
   Poklapa se sa odlukom od 09.08. i sa App Store-om. Ništa se nije menjalo.
2. **Politika privatnosti već pominje čuvanje fotografija** — „oko jedan dan,
   pa se brišu automatski", na srpskom i engleskom, i to se poklapa sa
   `interval '1 day'` u migraciji `0014_meal_photos.sql`. Nema nedoslednosti
   sa Data Safety formom.
3. **Screenshotovi se nisu morali pregenerisati** — postojali su lokalno od
   13.08. Problem je bio samo `.gitignore`.

**Dve stvari su iskrsle a nisu bile u planu:**

- `instance_type: linux_x2` **ne postoji u besplatnom tarifu**. Build je pao za
  1,8 s sa „The selected instance type is not available with the current
  billing plan". Prešlo se na `mac_mini_m2` — isti onaj koji iOS koristi;
  njegov image ionako nosi Android SDK. Uz to je `sed` morao da dobije prazan
  sufiks (`sed -i ''`), jer je macOS BSD sed.
- Drugi build je pao na `mergeReleaseResources`: **„The string `--` is not
  permitted within comments"**. Dva XML komentara u `android/app/src/main/res/`
  citirala su CSS tokene punim imenom, sa vodećom dvostrukom crtom. Nikad se
  nije videlo jer Android resurse do tada niko nije gradio. Popravljeno.
